# Pull Request Etiquette

Keep pull requests small enough to review in one sitting.

## Scope

Each pull request should address one logical change. If the description has to list
several unrelated fixes, split the work into separate pull requests so each one can
be judged on its own merits.

## Writing the description

Say what changed, why it changed, and how a reviewer can verify it. Link the related
issue or ticket so nobody has to ask for context.

## Responding to review feedback

Treat comments as notes about the code, not about you. Reply to every thread, even if
only with a short acknowledgement, and push follow-up commits instead of rewriting
history while the review is open.

## Keeping things moving

If a pull request sits unreviewed for more than two working days, re-request the
review or raise it in the team channel.
